# 第三方许可证与上游接口

以下信息说明项目与上游组件的关系。实际安装版本以各模块锁文件和容器清单为准，第三方组件按各自的许可证分发。

| 项目 | 核验结果 | 使用方式和边界 |
|---|---|---|
| Spring Boot | [仓库](https://github.com/spring-projects/spring-boot)，Apache-2.0 | Java 业务 API、事务和调度；保留 Apache license/NOTICE 要求 |
| FastAPI | [仓库](https://github.com/fastapi/fastapi)，MIT | 仅内部 Agent REST；API schema 是本项目自己的契约 |
| LangGraph | [Python 包元数据](https://github.com/langchain-ai/langgraph/blob/main/libs/langgraph/pyproject.toml)声明 MIT | 使用开源图构建/持久化；本项目不用托管 Platform/LangSmith 云能力 |
| Vue 3 | [核心包元数据](https://github.com/vuejs/core/blob/main/packages/vue/package.json)为 MIT | 前端框架依赖，固定 npm lock |
| Uptime Kuma | [仓库 LICENSE](https://github.com/louislam/uptime-kuma/blob/master/LICENSE)为 MIT | 本项目不 fork；可选运行官方镜像，使用 push adapter |
| PostgreSQL | [官方许可证](https://www.postgresql.org/about/licence/) PostgreSQL License | 业务库和独立 LangGraph checkpoint schema |

## Uptime Kuma 接口边界核验

[上游 Internal API Wiki](https://github.com/louislam/uptime-kuma/wiki/Internal-API)明确警示该 API 主要供应用自身使用，不保证第三方集成且可能破坏性变更；同页列出 Push endpoint `/api/push/<pushToken>`、status/message/ping 参数。规格因此把它隔离为可选 `UptimeKumaPushAdapter`，仅发 heartbeat；不调用 Socket.IO，不读写 monitor 配置，不同步事故。

API contract 检查按选定 Uptime Kuma 版本运行。若接口变更，默认关闭 adapter、保留 Dawnwatch 功能；不可悄悄依赖未承诺的内部接口。Push Token 位于路径，需防止 access logs、HTTP tracing、代理日志输出原值。

## Agent/模型接口核验

- LangGraph 使用 Python `StateGraph`/节点边/compile 和 checkpointer；保存结构化最小状态，`thread_id` 固定到 AgentRun ID。实现依赖签名以锁定版本的 reference 为准。
- Python 内部 API 只由 Java 调用；不直接暴露给 Vue 或公网。
- 模型厂商 API 的数据保留、训练使用、区域和日志策略按实际供应商/账号方案单独核验；不会由 LangGraph MIT 许可覆盖。
- 执行依赖扫描生成 SBOM 和许可证报告；AI 模型权重/Tokenizer 等均逐一登记来源、版本和许可证。

## 依赖清单与许可证声明

- Java 依赖由 [Maven 配置](../backend/pom.xml)声明。依赖审计脚本在 `backend/target/dependency-audit/` 输出报告。
- Python 运行依赖见[锁文件](../agent-service/requirements.lock)和[许可声明](../agent-service/THIRD_PARTY_NOTICES.txt)。`agent-service/audit_licenses.py` 从项目虚拟环境生成报告。
- 前端依赖见 [npm 锁文件](../frontend/package-lock.json)和[许可声明](../frontend/public/THIRD_PARTY_NOTICES.txt)。构建会将实际安装的依赖许可证及 NOTICE 复制到产物。

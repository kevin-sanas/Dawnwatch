# 测试与验收

## 如何运行

在 Windows 项目根目录使用 PowerShell。安装依赖和 JDK 设置见 [IDEA 启动与验收指南](../IDEA启动与验收指南.md)。

```powershell
.\scripts\agent.ps1 Test
.\scripts\backend.ps1 verify
npm --prefix frontend test
npm --prefix frontend run build
```

| 检查 | 覆盖范围 |
| --- | --- |
| Python | 诊断图、引用和风险校验、模型适配、评测及人评文件 |
| Java | 权限、监控、事件、人审、业务 PostgreSQL 和 Java 到 Python 的集成 |
| 前端 | 导航及返回上下文、状态展示、模型配置和质量中心数据 |
| 隔离演示 | 使用 `.\scripts\demo.ps1 -Check` 验证登录、合成故障、人审、回填、恢复与退出 |
| 核心验收 | 使用 `.\scripts\acceptance.ps1` 运行本机回归及核心业务旅程，在 `.cache/acceptance/` 生成报告 |

主要 CI 命令与运行环境见[工作流](../.github/workflows/backend.yml)。容器启动、恢复演练、真实模型评测及性能检查各有独立的验证条件。

## 手动验收

在 mock 环境使用合成服务及运行手册执行以下流程。

1. 使用管理员兼值班角色登录，登记或打开现有目标，确认检查已启用。
2. 令检查达到连续失败阈值，确认只生成一个活动事故，并核对事故时间线。
3. 确认事故并开始排查，发起诊断。逐条核对报告的检查与手册引用。
4. 批准建议并回填线下处理结果。恢复检查后，在时间线核对恢复阈值、观察和解决，再关闭事故。
5. 用观察员重新登录，验证被授权的详情可读，处理与审批动作不可用。

测试源代码、合成夹具和验证脚本随项目维护。生成的运行日志、截图、临时凭据和原始验收报告保存在本机 Git 忽略的目录。
